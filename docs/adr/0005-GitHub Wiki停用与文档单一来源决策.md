# ADR 0005: GitHub Wiki 停用与文档单一来源决策

- 状态：已确认
- 日期：2026-08-12
- 决策者：大仙
- 适用范围：`pinjie-fullstack-base`

## 背景

本仓库已经通过 `docs/` 保存产品需求、ADR、架构、业务蓝图和运维文档，并由 `docs/README.md` 提供完整导航。此前曾初始化 GitHub Wiki，并将 `docs/` 同步为 Wiki 页面。

实际使用发现，GitHub Wiki 的页面组织方式会弱化仓库目录上下文，仓库文档中的部分相对链接同步后也无法保持原有语义。同时维护仓库文档与 Wiki 副本会产生双重来源，增加链接失效、内容漂移和错误同步的风险。

## 决策

1. `docs/` 是本仓库项目文档的唯一存储和发布来源。
2. `docs/README.md` 继续作为全部项目文档的专项索引，保留目录结构和仓库相对链接。
3. 清空 GitHub Wiki 当前页面和同步清单，并关闭仓库 Wiki 功能。
4. 后续 Git 提交、推送和文档同步流程跳过 Wiki。即使历史 Wiki Git 远程仍可探测，也不得重新写入。
5. AI 不得初始化、重新启用、维护或同步本仓库 Wiki。只有用户未来明确改变本决策时，才能重新评估。

## 2026-08-29 文档载体边界补充

本 ADR 中的“项目文档”限定为 PRD、ADR、架构、蓝图和运维手册等专题项目文档。`docs/` 是这些专题文档相对于 GitHub Wiki 和其他外部副本的唯一存储和发布来源。

根 `AGENTS.md`、`PROJECT_INDEX.md`、`plans/`、`README.md`、`SECURITY.md` 和 `CHANGELOG.md` 分别承担长期规则、阶段导航、实施记录、项目入口、安全治理和交付历史职责，继续保存在现有稳定路径。它们属于明确的治理入口或历史载体，不构成 `docs/` 的重复副本，也不进入 `docs/README.md` 的专题文档登记表。

## 历史与恢复

Wiki 使用普通删除提交清空，没有改写历史。初始化提交 `5ac80bfc978e9a590d46266d6f44ce7c4d2c0252` 和删除提交 `b8f18c74cb0a6cf66074a95b9d34903aa7d5d84c` 保留在 Wiki Git 历史中。

如用户未来明确决定恢复 Wiki，应先重新评估文档目录和相对链接兼容性，再启用仓库设置，并使用普通恢复提交还原所需页面。不得直接恢复自动同步机制。

## 影响

1. 项目文档、评审链接和派生说明统一引用仓库 `docs/` 路径。
2. 不再维护 Wiki 首页、侧边栏、同步清单或 Wiki 专用链接。
3. `git-sync` 的通用 Wiki 能力在本仓库中被项目级规则禁用。
4. 原 Wiki 初始化计划继续保留，作为当时操作的审计记录，并追加本决策的后续事实。

## 验证要求

1. GitHub 仓库导航不显示 Wiki。
2. 访问仓库 `/wiki` 路径时不再进入 Wiki 页面。
3. Wiki 删除提交的当前树为空。
4. `AGENTS.md`、产品需求基线、文档索引、全项目索引和 Changelog 对文档来源的描述一致。
