# ADR 0012：统一文件资产采用可补偿本地存储

## 状态

已接受，2026-08-25。

## 背景

母版需要支持用户与管理员头像、文章图片、商品图片和通用附件，同时不能绑定商业云 SDK。文件写入是数据库事务之外的副作用；直接先写公开目录再提交元数据会产生孤儿文件，直接删除文件再提交数据库会在事务失败时丢失仍被引用的对象。

## 决策

1. 定义 `StorageProvider` 端口，当前只提供 `local` 驱动，未知驱动拒绝启动。
2. 本地上传采用私有 staging、`fsync` 和同文件系统 `os.replace` 原子提交；生产卷挂载 `/app/storage`，公开根为 `/app/storage/uploads`。
3. 文件键采用 `{scene}/{YYYYMMDD}/{hash[:16]}_{uuid}.{ext}`，原始文件名只进入元数据。
4. 去重范围固定为上传主体类型、上传主体 ID、场景和 SHA-256 哈希，不跨主体共享删除生命周期。
5. 删除采用“移入私有 trash、审计事务删除元数据、成功清理、失败恢复”的补偿流程。
6. 上传由 Web/Admin 双域 Cookie Profile 认证，并验证精确 Origin 与 Session 绑定 CSRF；资产列表和删除使用 RBAC，物理删除在 Admin 使用统一标准警告弹窗并写入审计。
7. 默认禁止 SVG，并同时校验扩展名、场景策略、体积、Magic Number 和 OOXML 内部结构。

## 后果

### 正面

- 母版无需云厂商依赖即可提供可运行的统一上传能力。
- 文件落盘与删除具有明确补偿语义，不把数据库回滚误当作文件回滚。
- 存储端口为派生项目接入对象存储保留稳定边界。
- 同主体去重降低重复占用，同时保持授权和删除所有权清晰。

### 代价与约束

- 本地驱动依赖单机持久卷，不提供跨节点共享、高可用或 CDN 原点能力。
- 数据库与文件卷需要在同一备份窗口内联合保护，单独恢复一侧可能产生悬空元数据或孤儿文件。
- trash 清理失败需要监控和人工核查；当前不提供后台垃圾回收任务。
- 对象存储不能照搬本地原子重命名，新增驱动必须重新设计确认与补偿语义。

## 未采用方案

- **直接绑定 S3/OSS/COS SDK**：增加母版依赖和厂商假设，留给有真实部署需求的派生项目。
- **把二进制写入 PostgreSQL**：放大数据库、备份和连接带宽负担，不适合作为通用静态资产方案。
- **跨主体全局物理去重**：删除与权限引用计数更复杂，当前收益不足以承担一致性成本。
- **上传后仅依赖定时清理孤儿文件**：会在主流程返回成功前留下不确定状态，不符合 Fail Closed 和明确补偿要求。
