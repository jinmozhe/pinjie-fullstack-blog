# ADR 0016：博客独立工程与维护边界

- 状态：已接受
- 日期：2026-09-09
- 范围：pinjie-fullstack-blog

## 背景

用户选择以当前全栈代码作为个人博客起点，要求独立 Git 历史、远端、需求、环境和维护流程，并已人工清理继承实施计划。母版的派生追踪要求与本项目目标不一致。

## 决策

1. 博客只配置自己的 origin，不保留母版远端、Tag/SHA 基线要求、升级同步流程或运行目录依赖。
2. 在可恢复保存旧 Git 元数据后初始化新的 main；首次提交和首次推送继续分别授权。不修改母版仓库或强制覆盖博客远端。
3. 博客需求采用 BLOG 编号，代码、安全、契约和测试基线按现有机制维护。保留运行必需的迁移和公共能力。
4. 用户已人工删除的计划不恢复，索引只登记现存计划；初始化后现存及新增计划继续永久保护。
5. 博客使用独立数据库账号、Redis 命名空间、Cookie、密钥、媒体和发布资源。生产目标未配置时发布入口必须失败。
6. 继承 ADR 和参考资料保留原决策背景；其母版身份、派生追踪、生产环境和验收数字不作为博客当前事实。博客当前行为以本 ADR、PRD、项目索引和实际源码为准。

## 替代范围

本项目内替代 ADR 0001 的通用母版产品定位、ADR 0004 与 ADR 0015 的母版基线登记和继承计划追踪要求。其他架构、安全、事务、迁移与质量约束继续适用。ADR 0014 的基础设施隔离原则保留，原生产部署记录仅作为参考。

## 后果与验证

博客自行承担后续维护和升级，不自动获取母版修改。取消追踪不取消博客自身发布、审计和回滚所需的 Commit SHA 或镜像 digest。

通过 Git 远端与历史检查、文档登记检查、环境与 Cookie 一致性检查、契约生成和三端轻量门禁验证。实际运行、测试、发布和部署分别按授权记录，不继承母版的通过结论。
