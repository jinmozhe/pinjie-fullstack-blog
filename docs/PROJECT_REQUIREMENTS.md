# Pinjie Fullstack Blog 产品需求基线

> 文档状态：生效
> 适用范围：独立仓库 pinjie-fullstack-blog
> 最后更新：2026-09-10

## 1. 项目定位

本项目是个人博客，提供一个管理员后台和一个无需登录的公开阅读网站。使用现有全栈代码作为工程起点，之后独立维护，不配置母版远端、不依赖母版目录、不登记母版版本基线、不建立升级同步流程。

本文件定义目标能力；源码、配置、迁移和生成契约证明实现，项目索引只描述阶段，当前实施和验证统一维护在博客首版全栈计划中。继承材料的产品目标、测试数字和部署记录均不能作为博客完成证据。

## 2. 用户与范围

- 管理员：仅项目所有者，复用管理员认证、RBAC、会话、上传、站点设置和审计，不增加作者、编辑等业务角色。
- 读者：匿名阅读公开文章，不需要账号。
- 首版不提供读者注册、用户中心、评论、留言、订阅、定时发布、服务端草稿、文章历史版本、内容回滚、永久删除或自动清空回收站。
- 工程初始化阶段保留现有通用模块，公开阅读阶段移除读者认证页面和入口并关闭服务端公开注册，不以大规模删除底层模块缩减产品界面。

## 3. 需求与验收

| 编号 | 需求 | 验收边界 |
| --- | --- | --- |
| BLOG-ENG-001 | 独立 Git、规则、需求和文档 | 只有博客 origin；新历史从博客首次提交开始；无需母版 Tag/SHA 或本机目录；提交推送独立授权 |
| BLOG-ENG-002 | 环境与数据独立 | 数据库账号、数据库、Redis 命名空间、Cookie、密钥、媒体目录和部署资源独立，不复制母版真实数据或凭据；本地统一使用 localhost 的 8000/3001/3000，多个项目同时启动须避免端口冲突；生产保留容器内部端口，同一服务器按项目分配映射端口并由域名反代分流 |
| BLOG-ADMIN-001 | 单管理员后台 | 复用现有管理认证和精确端点权限，不增加业务角色；后台页面遵守现有 Ant Design 和确认弹窗体系 |
| BLOG-POST-001 | Markdown 写作与直接发布 | 新建点击发布才入库；编辑保存立即更新；隐藏文章编辑后保持隐藏；失败保留输入、离开未保存页面提示 |
| BLOG-POST-002 | 稳定地址和文章生命周期 | slug 唯一且首次发布后不可改，回收站继续占用；公开/隐藏与 deleted_at 独立；恢复后隐藏，不提供永久删除 |
| BLOG-TAX-001 | 分类与标签管理 | 一篇文章最多一个分类和多个标签，均可为空；分类标签可新建编辑直接删除；删除与全部关联清理在同一事务完成 |
| BLOG-MEDIA-001 | 图片插入与引用保护 | 使用既有 article 上传场景；正文与封面引用由服务端核实；隐藏和软删除仍保护图片；单删和批量资产删除都拒绝在用图片 |
| BLOG-WEB-001 | 公开阅读 | 首页分页、文章详情、分类标签筛选、手机适配、SSR、基础 SEO、站点名称和简介；隐藏/删除内容及其元数据不从公开接口和缓存泄露 |
| BLOG-WEB-002 | 公开文章搜索 | 按关键词搜索公开且未删除文章的标题和摘要，结果支持分页；不检索正文，不以仅筛选当前页替代全站搜索；隐藏/删除内容不从搜索结果、计数或缓存泄露 |
| BLOG-TIME-001 | 统一时间语义 | published_at 首次发布时由服务端生成且不因编辑或重新公开重置；updated_at 单独更新；数据库 UTC，展示和日期筛选 Asia/Shanghai |
| BLOG-OPS-001 | 独立交付与恢复 | 默认轻量检查；专项测试、发布和部署分别授权；上线前验证数据库与图片备份可恢复；生产使用固定 digest |

## 4. 文章规则

- 内部主键沿用 UUID v7。正文以 Markdown 为权威内容，不保存历史正文副本。
- 公开状态只允许 public 和 hidden；deleted_at 独立表达软删除。
- 新建发布生成 published_at；后续编辑、隐藏、重新公开和恢复都不改变首次发布时间。
- 路径固定为 `/posts/{slug}`。slug 首次发布时确定，采用小写字母、数字和连字符；修改标题不改变地址。
- 软删除保留当前正文、分类、标签和资产引用；恢复后保持隐藏。回收站仅提供恢复。
- revision 仅用于并发写入校验，不构成版本系统。冲突时保留编辑内容并提示刷新，不静默覆盖。
- 未保存内容只保留在当前页面内存；浏览器崩溃或强制关闭可能丢失，不宣称具备草稿恢复。
- 默认按首次发布时间倒序，再按唯一 ID 排序。列表分页遵守现有统一契约。

## 5. 分类标签和批量操作

删除分类时清空所有文章的分类，再删除分类。删除标签时只移除所选标签的关联，保留文章和其他标签。关联范围包含回收站。

确认弹窗显示目标、受影响文章数量、文章保留和分类标签无法由文章回收站恢复的说明；批量操作按文章去重统计。提交时重新核对影响范围，发生变化需刷新确认。事务内完成解除关联、删除和审计，失败整体回滚。

文章提供批量软删除与批量恢复，分类标签提供批量删除。前端不得循环单条请求模拟批量事务，继续沿用后端批量数量、权限、防重和锁定顺序规则。

## 6. Markdown 与媒体

编辑器提供输入、预览、常用工具栏、代码块和图片插入。预览与公开页面复用同一套安全渲染规则，禁用原始 HTML 和可执行内容，校验链接与图片协议。

使用本站受控资产路径，禁止写入本机路径或依赖后台域名。服务端解析实际正文和封面引用并在文章保存事务中更新引用关系；图片删除与引用写入遵守一致的锁定规则。未引用资产由管理员人工清理，首版不做自动回收。

图片引用保护独立于媒体访问权限。文章隐藏或软删除后，已知图片直链继续可访问；文章隐藏不提供图片保密能力。不对已公开图片承诺撤回第三方副本。隐藏和回收站中的文章继续保留图片引用，拒绝删除正在使用的资产；解除全部引用后才可由管理员清理。

## 7. 公开网站与时间

公开列表、详情、搜索、分类标签入口及其计数、站点地图和 Metadata 统一仅查询 public 且 deleted_at 为空的文章；分类标签入口只展示与这类文章关联的分类和标签。不存在、隐藏或软删除的文章统一返回 404；依赖故障明确返回服务异常，不伪装成空列表或不存在。

首版内容按请求读取，明确禁止会在隐藏后继续返回正文的页面、接口和代理缓存。提供准确标题、描述、canonical、文章结构化数据和站点地图。公开网站提供分类标签筛选与标题、摘要关键词搜索，日期筛选先用于后台。搜索无结果保留查询并提供清除入口，依赖失败明确显示服务异常；接口与查询设计在第三阶段实现计划中确定。

首页、分类页、标签页和文章页分别具有可独立访问的地址、标题、描述和 canonical。首版元信息从站点设置、文章标题摘要及分类标签名称生成，不新增独立 SEO 编辑字段。分类和标签使用已有 slug；搜索结果页不进入索引。页面元信息与正文遵循相同公开范围，不依赖客户端加载后才能呈现主要阅读内容。

视觉与交互统一遵守 [Web 统一设计标准](architecture/web-design-standard.md)，本需求不重复维护颜色、字号、间距及组件外观数值。设计标准建立不代表页面与搜索已实现。

日期筛选采用北京时间开始日零点包含、结束日次日零点不包含的区间，转换成 UTC 查询；发布时间不允许输入未来日期，不设置调度任务。

## 8. 工程与安全基线

继续维护 FastAPI 模块化单体、独立 Admin/Web、仅经 packages 公共入口共享、唯一根 OpenAPI 和生成 API Client。契约顺序为后端实现、导出 OpenAPI、生成客户端、前端适配。

继续执行服务端权限、CSRF、HttpOnly Cookie、审计、失败明确传播、事务一致性、Alembic 迁移、受控依赖和不可变发布规则。迁移链完整保留。真实 .env、秘密和生产数据不得入库；资产文件、配置媒体和数据库分别备份。

现存和新增计划永久保留，只能由用户人工删除。用户清理旧文件后按当前文件事实重建索引，不要求保留失效登记。

## 9. 分阶段交付

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 第一阶段 | 工程独立化、规则需求、Git、环境和发布隔离 | 能独立安装和维护，运行前置条件与验证事实明确，不依赖母版 |
| 第二阶段 | 数据模型、API、后台写作、分类标签和资产引用 | 管理员能完成发布、编辑、隐藏、删除和恢复 |
| 第三阶段 | 公开阅读、标题摘要搜索、SEO、时间、移动端 | 匿名读者可正常阅读与搜索，隐藏及删除文章不从公开读取链路泄露 |

首版使用同一份全栈实施计划。第一阶段完成不代表文章已实现或生产可用。

## 10. 验证与上线

日常自动检查限于现有轻量门禁；Markdown、文档、边界与契约按影响验证。pytest、Vitest、production build、Playwright、测试数据库迁移只有在用户明确点名应用和范围后执行。

上线前授权验证完整写作阅读链路、危险 Markdown、图片保护、分类标签事务、时区边界、移动端和备份恢复。数据库与媒体存储须使用博客自己的目标。提交、推送、镜像发布、部署及生产操作各自授权；未执行项不得记为通过。
