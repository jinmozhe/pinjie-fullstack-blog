# Web 统一设计标准

## 1. 适用范围与权威关系

本文是 `apps/web` 视觉与交互设计的唯一详细标准，适用于页面、布局、组件、样式、正文排版及相关评审。强制执行入口为 [Web 项目规则](../../apps/web/AGENTS.md)；产品能力以 [产品需求基线](../PROJECT_REQUIREMENTS.md) 为准，单次实施与验证进入 [首版全栈计划](../../plans/2026-09-09_博客首版全栈实施计划.md)。架构、安全、错误语义和验证授权继续遵守应用及仓库规则。

首版采用暖灰纸色、克制的绿色强调、清晰文字层级和轻量圆角卡片。首页以文章为中心，首屏尽早展示真实内容。桌面左栏承载搜索、分类和标签，右侧为紧凑简介与文章；手机使用导航面板。视觉方向参考 Senna，具体数值和行为以本文为准。效果图中的名称、文章、分类和封面属于示例，不构成产品数据或必须使用的资产。

当前公开阅读页面已接入本标准：globals.css 提供统一变量、基础与正文样式，Tailwind 3 提供布局，components/ui 提供 shadcn/Radix 基础组件，features/blog 组合首页、分类、标签、搜索与文章阅读。读者登录、注册和账户入口已关闭，通用底层模块保留。源码接入不代表生产构建、浏览器视觉或 WCAG 完整验收通过，实际验证记录以原计划为准。

本文第 2 至 5 节的具体配色、字号、布局和组件外观属于项目设计选择；第 6 节引用行业可访问性要求。首版固定浅色主题，不提供主题切换。本文不适用于 Admin，后台继续沿用其 Ant Design 体系。

## 2. 设计变量

### 2.1 来源与使用

- 本文定义变量语义与目标值。后续实现以 `apps/web/src/app/globals.css` 中集中声明的 CSS 变量作为唯一运行时来源，Tailwind 映射及组件引用同一组变量，禁止再维护独立调色板或页面私有字号体系。
- 下列变量已接入公开阅读样式。新增或修改变量时核对全部实际消费者，禁止让同名或近义变量意外改变用途；迁移在当前授权范围内原子完成，不保留无期限别名和双套主题。
- 沿用 Next.js、React、Tailwind CSS，以 shadcn/ui 为定制组件标准、Radix UI 为无样式交互底层、lucide-react 为图标来源。按实际需要接入组件，普通语义化链接和内容容器无需包装成高阶组件。
- 新增依赖前确认现状和必要性，遵守 workspace 锁文件及依赖准入。不得为套用上游新版主题示例升级 Tailwind、引入第二套 UI 框架或改写既有工程边界。
- 页面内可以有内容驱动的局部布局值；可复用的颜色、字号、间距、圆角和交互状态必须进入统一变量。扩展前先确认已有语义能否复用，确需新增时同时更新本文及实现。

### 2.1.1 组件与样式分工

组件体系采用分层复用：页面调用博客业务组件和项目内的 shadcn 基础组件，基础组件使用 Tailwind 样式与选定的 Radix Primitives。Radix 是本项目的选择，不意味着上游所有 shadcn 组件都强制依赖 Radix。普通内容元素不需要引入交互库。

| 层次 | 职责与使用边界 |
| --- | --- |
| CSS 变量 | 在 globals.css 集中定义主题和设计值，作为唯一运行时来源 |
| Tailwind CSS | 使用当前 3.x 配置，负责布局、响应式和组件样式，不复制独立主题值 |
| shadcn 基础组件 | 源码进入 components/ui 后由项目维护；按钮、输入、导航面板、分页等按需接入，优先复用 variants |
| Radix Primitives | 封装复杂控件的焦点、键盘与模态交互；页面通常通过基础组件调用 |
| 博客业务组件 | 在 features/blog 组合文章卡片、分类导航、标签与阅读正文，路由不重复实现 |
| 集中 CSS | 保留基础重置、正文排版和确有需要的复杂选择器，不为各页面维护重复样式体系 |

依赖与生成配置必须适配仓库已锁定版本。不得直接运行默认初始化覆盖现有主题，也不以缺少某一个包判断所有组件是否接入；结合 components.json、组件源码、构建配置及实际引用核验。使用 Tailwind 不免除布局设计，使用现成组件不免除业务组合与可访问性验收。

| 辅助文字 / 五种背景 | 最低 4.51:1 | 普通文字，不能再降低不透明度 |
| 链接 / 五种背景 | 最低 5.12:1 | 普通文字，正文链接另加下划线 |

## 3. 页面布局与响应式

### 3.1 首页骨架

- 左栏按站点标识、搜索、文章分类、全部标签顺序排列。分类默认含“全部文章”，标签统一字号并自然换行；数量较多时保证完整内容可通过滚动或有名称的展开控件访问，不只保留热门项。
- 左栏宽度为 248px，与右侧内容并列，不覆盖内容；可使用 sticky，最大高度随动态视口变化并允许内部纵向滚动。焦点项、标签和底部信息不得被固定页脚盖住。
- 右侧主容器最大外宽为 1280px，使用 `border-box`，包含左右内边距；在扣除左栏后的可用区域居中。文章网格使用可收缩列，子项设置 `min-width: 0`。
- 顶部简介只放站点标题与简短介绍，桌面按约 160px 的内容区域设计，不设固定高度或裁切。首屏优先露出文章，禁止大幅装饰图、订阅表单和整屏宣传占位。
- 简介仅在未筛选的首页第一页展示；分类、标签或搜索结果改用对应上下文标题与清除条件入口，不重复占用简介空间。
- 列表按产品约定分页与排序。UI 不提供没有后端能力支撑的热门排序、阅读量或推荐标记。

### 3.2 尺寸与断点

断点以下表 CSS 视口宽度为准，临界点归入较宽的一档。320px 以下仍应尽量自然重排，不以页面最小宽度制造溢出。

| 视口宽度 | 导航 | 文章列数 | 主容器左右内边距 |
| --- | --- | --- | --- |
| 小于 360px | 手机导航面板 | 1 | 16px |
| 360px 至小于 768px | 手机导航面板 | 1 | 20px |
| 768px 至小于 1024px | 导航面板 | 2 | 32px |
| 1024px 至小于 1280px | 248px 左栏 | 2 | 40px |
| 1280px 及以上 | 248px 左栏 | 3 | 40px |

网格间距为 24px；极窄屏继续单列，不缩小正文来容纳更多卡片。手机顶部保留站点标识与有名称的导航按钮。导航面板宽度为 `min(320px, calc(100vw - 32px))`，高度随动态视口，允许内容滚动并考虑安全区域。

### 3.3 阅读页容器

文章正文最大宽度为 720px，包含正文的布局列必须可收缩；手机沿用页面边距。正文之外的分类、标题、日期和可选封面保持清晰层级，不强制为长文保留首页三列网格。目录等阅读辅助能力按实施计划接入，出现时不得挤压正文、覆盖内容或制造多层固定滚动区域。

## 4. 基础组件与状态

### 4.1 交互共性

- 导航使用链接，改变本页状态或执行动作使用按钮；禁止可点击 `div` 替代原生控件，禁止链接内嵌按钮或链接。图标统一使用 lucide-react，常规尺寸 16px 或 20px，装饰图标对辅助技术隐藏。
- 独立主要控件默认至少 44px 高，图标按钮点击区域默认至少 44px × 44px；尺寸允许随文字放大增长。图标按钮必须具有可访问名称，Tooltip 仅作补充且支持键盘，不作为唯一名称来源。
- 默认文字采用对应背景前景色；非选中项悬停采用 `--accent`，选中项采用 `--primary` 配对。正文链接保留下划线，悬停使用 `--link-hover`。
- 焦点使用至少 2px 的 `--ring` 实线轮廓和 2px 外间隔，深色控件外增加浅色间隔；不得移除焦点或用与背景近似的阴影替代。元素选中时仍必须有独立焦点提示。
- 当前导航、标签筛选和页码根据语义使用 `aria-current` 或 `aria-pressed`，不得将普通导航伪装成 ARIA Tabs。禁用项明确不可操作；`aria-disabled` 本身不阻止事件，需要落实真实行为。
- 加载、失败和成功消息使用清晰中文；加载区域保留合理尺寸，适用时设置 `aria-busy`。搜索结果数量等变化采用非打断式状态播报，避免每次按键都触发警报。

### 4.2 控件约定

| 组件 | 默认与交互 | 边界状态 |
| --- | --- | --- |
| 搜索框 | 使用语义化搜索表单，输入有持久的可访问名称；占位文案为“搜索文章”；Enter 和有名称的提交按钮可提交，清除按钮可撤销输入 | 搜索范围为标题和摘要；无结果保留查询与清除入口，错误明确显示且保留输入；不以仅搜索当前页模拟全站搜索 |
| 分类导航 | “全部文章”与分类链接纵向排列；当前项高亮并提供语义状态 | 长名称自然换行，不缩小字号；无分类文章仍进入全部文章；公开分类范围遵守公开内容过滤 |
| 标签 | 分类区域下方展示全部公开内容使用的标签；统一字号，默认浅色，悬停和选中态符合统一配色 | 长标签可换行；没有标签时省略标签区；折叠时显示可访问的展开入口，不能永久隐藏剩余标签 |
| 文章卡片 | 封面 2:1，封面和标题指向详情；分类与标签有各自链接；分类、标题、摘要、日期构成内容层级 | 标题完整展示并允许换行；摘要最多三行且不承担独有操作信息；无封面使用文字布局，无摘要或分类标签时移除相应空槽 |
| 分页 | 使用具有实际地址的链接，当前页有文本与视觉状态；上一页、下一页名称明确 | 首尾不可用项使用非链接或真实禁用控件；无分页需求时省略；窄屏减少中间页码但保留当前页和前后入口 |
| 手机导航 | 从左侧展开，使用 Radix 对话框语义或等价的完整可访问实现，提供标题和关闭按钮 | 打开后焦点进入面板，Tab 留在面板内；Esc、关闭按钮及遮罩可关闭；关闭后恢复到触发按钮或合理的导航后焦点位置 |

手机导航打开时背景不可交互，锁定背景滚动并保持面板滚动；关闭后恢复原滚动位置。切换至桌面断点时必须解除遮罩、滚动锁和模态属性，不能留下不可操作页面。浮层打开和关闭不应使页面宽度跳动。

搜索、分类、标签与分页应能通过 URL 恢复上下文。具体参数、条件组合与接口契约在对应实施计划中统一，不在设计文档另造 API 类型。日期按产品规定的 Asia/Shanghai 展示，列表日期文字清晰，不仅显示含糊的相对时间。

### 4.3 页面反馈

| 场景 | 展示要求 |
| --- | --- |
| 尚无公开文章 | 显示“暂无文章”，不展示虚假文章或空分页 |
| 分类、标签或搜索无结果 | 保留条件，说明无匹配内容并提供清除入口 |
| 加载 | 骨架与最终布局接近，尊重减少动效偏好，不使用虚假业务内容 |
| 依赖或请求失败 | 显示“加载失败”及可执行的重试；不伪装成空列表或 404，不泄露内部错误信息 |
| 不存在、隐藏或删除文章 | 按产品约定统一 404，页面及元数据不展示原文标题、摘要或封面 |
| 操作成功 | 适用的本地操作提供简短状态反馈，不为只读浏览虚构成功通知 |

## 5. Markdown 正文排版

- 页面文章标题作为主标题，正文按内容结构递进。保留语义标题层级，不能仅用大号加粗段落代替标题；有正文 h5、h6 时保持语义并采用正文尺寸的强调样式，不继续缩小字号。标题到内容间距 16px，二级标题前 40px，其他子标题前 32px。
- 正文采用 `--text-prose`，自然左对齐；段落之间 24px。列表使用原生有序或无序语义，缩进 24px，列表项间距 8px，嵌套结构不超过可阅读的内容宽度。
- 正文链接使用链接色与下划线，有明确目的描述；长 URL 允许换行。新窗口链接在确需使用时提供相应提示，保留现有安全协议校验。
- 引用采用代码背景、16px 内边距和左侧装饰线，保留 `blockquote` 语义，避免再包一层卡片。引用与上下文间距 24px。
- 行内代码使用等宽字体、代码背景及小幅内边距，长内容可换行。代码块使用 14px 等宽字体、1.7 行高、16px 内边距和 8px 圆角，在自身区域横向滚动，保留预格式内容。若接入语法高亮，全部语法颜色须另行检查，不能直接认为第三方主题合格。
- 表格使用表头和必要的标题说明，单元格建议垂直 12px、水平 16px 内边距；宽表使用有名称的局部滚动区，保证键盘可访问。代码和表格的局部滚动不得扩展为整页横向滚动。
- 正文图片最大宽度 100%、高度自适应，保留原始比例；内容图片不得套用卡片封面的裁切规则。信息图片有合适的替代文字，装饰图片使用空替代文字；可获取尺寸时预留比例空间，减少布局跳动。
- 封面只在数据存在时展示，不强制配图。图片加载失败保持页面结构并提供可理解的替代信息，不生成未经授权的封面或引入不受控外站图片。
- 后台预览与公开正文复用后端安全渲染规则，本文仅规定表现。禁止为目录、样式或高亮新增另一套不一致的 Markdown 解析和安全策略；链接、图片协议和 HTML 限制遵守产品及内容架构。

## 6. 可访问性基线

以 WCAG 2.2 AA 的适用成功准则为验收依据。下列是重点清单，不能替代完整适用性判断，也不能据此宣称未实现或未验证页面达到 AA。

1. 普通文字对比度至少 4.5:1，大号文字至少 3:1；大号文字的 WCAG 判定为至少 18pt 常规或 14pt 粗体，不能把项目 20px 标题自动认作可降低标准的大字。必要的控件边界、状态和图形与相邻颜色至少 3:1，纯装饰分隔线不承担此职责。
2. 内容在相当于 320 CSS px 宽度时重排，除理解所必需的二维内容外，不要求同时横向和纵向滚动。支持 200% 文字放大；同时核对 1280px 视口下 400% 缩放的重排场景。固定栏、页脚、裁切和绝对定位不能遮住文字或控件。
3. 用户覆盖文本样式为行高 1.5 倍、段后间距 2 倍、字距 0.12 倍、词距 0.16 倍字号时，适用的文本不能丢失内容或功能。这是用户调整后的兼容要求，不是全部页面的默认排版值；中文按实际使用的文本属性核对。
4. 所有操作支持键盘和合理的 Tab 顺序，焦点始终可见且不被作者创建的内容完全遮挡；本项目进一步要求关键焦点轮廓完整可见。提供跳过重复导航进入主要内容的入口，不以 hover 独占任何功能。
5. WCAG 2.2 AA 的点击目标最低为 24px × 24px，符合规范的间距、等价控件、行内文字等情形有例外。本项目独立主要控件采用至少 44px 的设计基线；标签等紧凑控件至少满足 AA 的尺寸或间距要求，触屏状态适当扩大。行内正文链接不强制变成 44px 按钮。
6. 使用 `header`、`nav`、`main`、`article`、`aside` 等适当语义，导航区域有可区分名称。主内容有清晰主标题；图标按钮、搜索框、展开控件和对话框都有可靠的可访问名称。
7. 颜色不作为唯一信息通道，选中态、错误和状态变化同时提供文字、形状或语义信息。提示消息使用合适的状态播报，模态面板遵守焦点与背景隔离规则。
8. 响应 `prefers-reduced-motion: reduce`：关闭导航位移动画、骨架流光和非必要平滑滚动，必要状态反馈仍应即时可见。禁止自动播放或循环装饰动效影响阅读。

## 7. 实施、评审与验收

### 7.1 接入顺序

1. 读取完整标准并在当前计划标明影响范围、适用条款与验证方式；不因纯 API 或文档修改触发无关视觉重做。
2. 核对现有变量、样式入口和公共组件，先接入颜色、字体、间距等语义变量，再接入基础组件和页面。共享变量变更必须覆盖所有实际受影响消费者。
3. 在页面接入时复读容器、选择器、导入和组件引用，确认标准在目标页面实际生效。公共样式存在不代表页面已经遵守标准。
4. 逐项覆盖成功、加载、空数据、失败和适用的操作反馈。保留领域行为、接口契约与页面输入，不为统一视觉删减功能。
5. 按下面的验证边界交付，并把标准与实现差异记录在原计划；偏离基线的设计决定须有明确原因和范围，不能为单个页面复制一份独立设计标准。

### 7.2 检查范围

| 变更类型 | 默认检查 | 结果边界 |
| --- | --- | --- |
| 标准、规则与索引 | 根 `pnpm lint:md`、`pnpm check:text`、`pnpm check:documents`、`pnpm check:workspace`、`pnpm check:boundaries` 及差异检查 | 文档与治理结果，不代表页面符合视觉标准 |
| Web 页面、样式与组件实现 | Web 规则规定的 typecheck、lint，受影响的文档、依赖或契约检查 | 静态检查不能替代浏览器或交互验收 |
| 专项动态验证 | 仅执行用户当前任务明确点名的 build、Vitest、Playwright、axe 或其他范围 | 未授权项写为“按项目策略未执行”，不写为通过 |

配色辅助核算应覆盖实际前景、背景、透明度和状态，但数值核算不是全站可访问性认证。本仓库当前没有专门验证全部设计变量、字号或视觉一致性的自动门禁，评审清单和静态检查不能冒充这一能力。

获授权的浏览器验收至少按影响核对：320px、390px、768px、1024px、1280px、1440px；涉及断点时核对临界值前后；长标题、无封面、长标签、空列表、失败、404；搜索与分页的上下文；导航打开关闭及跨断点恢复；键盘焦点、文字放大、文本间距和减少动效。正文变化还需覆盖长 URL、图片、嵌套列表、代码和宽表格，检查 `document` 横向溢出、遮挡、嵌套卡片、圆角、阴影与业务配色。

测试和视觉验证结束后按根规则核对本次服务 PID、监听端口和测试标签，只清理可确认归属的临时资源，禁止结束 Browser Use 总会话。没有执行的验证、保留的服务和剩余风险必须如实记录。
