# 博客内容与公开阅读架构

## 适用范围

本文描述后台写作与第三阶段公开阅读的源码机制。产品范围以 [博客需求](../PROJECT_REQUIREMENTS.md) 为准，启用步骤见 [博客后台启用与写作](../operations/blog-writing.md)。公开接口、阅读与搜索页面已接入现有文章模型；真实迁移、业务测试与浏览器验收按原计划中的实际验证记录判断。

## 分层与契约

| 位置 | 职责 |
| --- | --- |
| `app/domains/blog/schemas.py`、`router.py` | 输入约束、响应、管理员权限与 CSRF 接入 |
| `app/domains/blog/rules.py` | 安全 Markdown 渲染、时间区间、并发和生命周期规则 |
| `app/services/blog.py` | 写作、分类标签删除、资产校验与事务审计编排 |
| `app/db/models/blog.py`、`app/db/repositories/blog.py` | 五张内容表、查询、数据库锁和持久化 |
| `app/services/assets.py`、`app/db/repositories/asset.py` | 资产删除时检查文章引用 |
| `apps/admin/src/features/blog/` | 文章列表、回收站、编辑器、分类和标签管理 |
| `apps/admin/src/lib/api/blog.ts` | 使用生成 DTO 和现有 HTTP 管道访问后台接口 |

管理接口位于 `/api/v1/admin/blog`，提供文章列表、详情、发布、保存、状态切换、单条及批量删除恢复、Markdown 预览、分类标签管理及删除影响预览。精确方法、字段与响应以根 `openapi.json` 为准。客户端由 `pnpm generate-api` 生成，不另存 DTO。

端点使用现有管理员权威会话，按 `posts:*`、`categories:*`、`tags:*` 检查权限；写入和预览要求 CSRF。成功响应为 `Cache-Control: no-store`。博客请求正文不进入错误请求体采集，审计只记录动作、对象及字段名称等必要信息，不保存正文历史。

## 数据与生命周期

- `posts` 保存当前文章；`categories`、`tags` 各自维护唯一名称和 slug；`post_tags` 保存多标签关联；`post_assets` 保存正文与封面引用。
- 新文章只有点击发布才入库，初始状态为 `public`；修改正文不会改变状态。`hidden` 与独立 `deleted_at` 可以同时存在。
- 软删除保留正文、slug、分类标签和资产引用。恢复清空软删除字段并改为 `hidden`，首次发布时间不变。没有永久删除、自动清空或历史版本接口。
- slug 发布后不可修改，回收站继续占用。`revision` 是并发校验号，不是可回滚的文章版本。
- 服务端首次生成带时区的 `published_at`，后续保存、隐藏、再次公开均不重置；`updated_at` 单独变化。列表按首次发布时间和 UUID 倒序稳定分页。
- 北京时间筛选把开始日零点和结束日次日零点转换为 UTC 半开区间。后台展示显式使用 `Asia/Shanghai`，Windows 通过锁定的 `tzdata` 提供时区数据。

输入上限：标题 200 字符、摘要 500 字符、正文 200000 字符、slug 120 字符、分类标签名称 80 字符；每篇最多 20 个标签和 100 张不同正文图片；每次批量操作 1 至 100 个不同目标。

## 事务与并发

所有博客写操作通过现有 `AuditCoordinator` 提交业务变更和成功审计，异常整体回滚。写事务首先获取 PostgreSQL 事务级 advisory lock `(20260909, 1)`，串行化本博客内容写入，适配单管理员写作规模；数据库锁等待上限为 5 秒，超时返回明确服务错误。后续按需要锁文章、分类标签和按 UUID 排序的资产。资产删除只获取自己的资产行锁，不等待博客 advisory lock。

文章与分类标签编辑、状态修改、软删除和恢复检查客户端读取时的 `revision`；变化时返回 412，整批不执行。前端冻结编辑起点与输入，失败保留内容，由用户保留所需文字后重新加载。

分类标签删除先返回目标名称、包含回收站的受影响文章数及摘要。确认请求在写锁内重新计算目标 revision 和关联文章 revision 摘要，不同则返回 412，要求重新预览。确认一致后在同一事务清空分类或移除所选标签关联、更新受影响文章 revision，再删除分类标签；文章和其他标签保留。分类标签没有回收站。

## Markdown 与图片

后台预览和公开展示共用后端 `render_markdown`。使用 `markdown-it-py`，明确关闭原始 HTML，支持代码块、表格和删除线。链接只接受相对地址及 HTTP、HTTPS、mailto，拒绝危险协议、协议相对地址和控制字符。无效链接不会产生可执行链接，不加载不受控渲染插件。

正文图片从 Markdown token 提取，覆盖引用式语法，排除代码块示例。实际图片仅接受本站 `/static/uploads/article/` 受控路径，不接受外站、查询参数、片段和路径穿越。保存时确认图片是现存管理员 article 场景的图片资产，并把正文与封面资产集合写入 `post_assets`。

文章保存锁定新旧全部资产，资产删除持有同一资产行锁后检查引用，数据库外键提供最后约束。公开、隐藏和回收站文章均受到图片删除保护；软删除不会自动删除图片。正文编辑撤除引用并保存后，未被其他文章或头像引用的旧资产可由管理员确认清理。

已知图片直链始终按公开静态文件访问，隐藏或软删除文章不撤销直链。未提交文章中的上传图片已经独立落盘，不属于服务端草稿；放弃编辑后的未引用图片可从资产列表人工清理。上传、引用和删除的存储补偿机制见 [文件资产架构](file-asset-storage.md)。

## 公开读取、搜索与页面

`app/db/repositories/public_blog.py` 是独立只读模型，`app/services/public_blog.py` 负责呈现与错误分类，`app/domains/blog/public_router.py` 只处理协议，使用独立匿名依赖。公开 DTO 单独定义在 `public_schemas.py`，排除状态、revision、删除时间、内部资产 ID、原始 Markdown 和内部文章 ID。字段及方法的机器权威来源仍为根 OpenAPI。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/blog/posts` | 分页文章列表，默认 12 条、最多 100 条；page 从 1 开始，最大 1000000 |
| `GET /api/v1/blog/posts/{slug}` | 公开文章详情与安全渲染 HTML，不存在、隐藏、软删除统一 404 |
| `GET /api/v1/blog/taxonomy/{kind}` | 分页分类或标签及公开文章计数，kind 为 categories/tags |
| `GET /api/v1/blog/taxonomy/{kind}/{slug}` | 单个公开分类或标签；没有关联公开文章时返回 404 |

列表接受 q、category、tag，筛选组合为交集。q 去除首尾空白后对标题和摘要执行大小写不敏感的字面包含搜索，最大 100 字符；SQLAlchemy 自动转义通配符并使用绑定参数，百分号和下划线不成为查询通配符，不检索正文。暂不引入全文搜索引擎或新的索引迁移。

列表、计数、详情、分类标签以及站点地图每次读取均过滤 public 且 deleted_at 为空。列表不加载 Markdown，分类标签和封面使用批量查询，避免逐文章加载。数据库失败映射 503，失败与空数据严格区分；公开 API 的正常响应和已处理错误均设置 no-store。不能把运行前未执行内容表迁移的故障解释为暂无文章。

Web 路由为 `/`、`/posts/{slug}`、`/categories/{slug}`、`/tags/{slug}` 和 `/search?q=...`，page 参数承载分页；超过已有页数的后续页返回不存在，首页空列表正常显示暂无文章。分类标签描述从名称生成，SEO 不增加管理字段。公开导航展示全部有关联公开文章的分类和标签，按后端分页读取后组合，数量随内容规模增长。

## SEO 与缓存边界

- 根布局只管理公开 origin、站点标题模板和默认描述，不继承首页 canonical 给所有页面。各阅读页提供独立标题、描述、canonical 和 Open Graph；搜索页 noindex，robots 保留抓取能力让搜索引擎读取 noindex。
- 文章详情和 Metadata 使用相同请求级读取函数；Next.js 16 params 按 Promise 解包。标题使用根模板，不重复拼接站点名称。JSON-LD 序列化转义小于号及行分隔符，避免文章标题闭合 script；不伪造作者信息。
- `htmlLimitedBots: /.*/` 关闭流式 Metadata，对所有访问方先完成元信息和内容可见性检查，减少已输出成功状态后才判断文章不存在的风险。动态 HTTP 状态行为仍须通过获授权的浏览器或构建验收确认。
- Server Components 使用生成 SDK 的 Axios 客户端，具有 10 秒请求超时，不跟随重定向，不转发读者或管理员 Cookie。React cache 仅在本次服务端渲染内去重，不启用跨请求正文缓存、ISR 或 Redis 内容缓存。阅读链接使用原生文档导航，不预取或复用 RSC 历史内容；已下载页面及第三方副本不具备远程撤回能力。
- `/sitemap.xml` 返回索引，`/sitemaps/{kind}/{page}` 每次仅查询至多 100 项，主页加入文章第一分片；仅导出公开文章与有关联文章的分类标签。索引最多 50000 个分片，超限或依赖失败明确返回 503，分片不存在返回 404，所有响应 no-store。精确 lastmod 未加入分类标签分片，避免声明不可靠修改时间。
- 站点配置失败不使用示例品牌或空内容，进入中文错误边界；根布局失败使用独立 global-error 保证最低限度可恢复操作。部署前必须配置正式 WEB_PUBLIC_ORIGIN。

## 迁移与验证边界

增量迁移 `20260909_01` 基于 `20260829_01` 增加五张表，不重建旧迁移。降级入口明确拒绝自动删内容表，已有文章后采用前向修复或经授权的数据库及图片备份恢复。

Backend 安全规则、API 权限、数据库生命周期与并发，以及 Admin 关键交互已有测试源码。默认只运行项目轻量门禁；pytest、Vitest、数据库迁移、构建和浏览器验证必须按本次任务授权执行。测试源码和静态检查不能证明真实写作链路、迁移或页面体验通过。
